## 1. 使用nest-cli创建nest项目的两种方式

### npx

```js
npx @nestjs/cli new 项目名 // 直接使用npx执行, npm会把它下载下来然后执行
```

### 全局安装nest-cli

```js
// 安装到全局(需要时不时的更新一下版本,否则用它创建的项目版本可能不是最新的),然后执行(推荐)
npm install -g @nestjs/cli

// 创建nest项目
nest new 项目名
```

## 2. nest-cli提供的命令

### nest -h

```js
nest -h // 查看nest-cli提供的所有命令,会以表格形式展示
```

### nest new

```js
nest new // 用于创建新项目
```

其他选项

```js
// nest new命令下的其他选项:
--skip-git // 简写为 -g,表示创建项目时不初始化git仓库. 例: nest new x -g
--skip-install // 简写为 -s,表示创建项目时不执行npm install. 例: nest new x -s
--package-manager // 简写为 -p,指定包管理器,创建项目时会让你选择. 例: nest new x -p pnpm
--language // 简写为 -l,表示项目使用js/ts,默认为ts. 例: nest new x -l typescript
--strict  // 表示ts的编译选项是否开启严格模式,默认为false. 例: nest new x --strict true
```

### nest generate

其他选项

```js
// nest generate命令下的其他选项:
--flat和no--flat // 表示是否生成对应目录,默认是--flat
--spec和--no--spec // 表示是否生成测试文件,默认是--spec
--skip-import // 表示不在AppModule里引入,例如生成的module.ts文件,不会自动引入到app.module
--project // 指定生成代码在哪个子项目的,menorepo
```

可以使用nest generate命令来生成controller/service/module等文件.

```js
nest generate module x // 会自动生成x.module.ts文件,并会自动在app.module中引入

nest generate controller x // 会自动生成x.controller.ts文件,并会自动更新到x.module.ts的controllers中.

nest generate service x // 会自动生成x.service.ts文件,并会自动更新到x.module.ts的providers中.
```

如何使用nest generate 生成一个完整的模块

```js
nest generate resource x
/* 
生成一个完整的模块,模块名字为x. 终端回车后,会提示你选择需要生成哪种风格的代码,因为nest支持http/websocket/graphql/tcp等.

- REST API
- GraphQL(code first)
- GraphQL(schema first)
- Microservice(non-HTTP)
- WebSockets

例如选择REST API风格的代码后,会提示你是否需要生成CRUD代码,选择是后就会生成整个模块的CRUD+REST API的代码,当然也会自动在AppModule中引入.
**/ 
```

### nest build

```js
nest build // 执行nest build,会在dist目录下生成编译后的代码
```

其他选项

```js
nest build -h // 查看nest build指令下的其他选项

--webpack和--tsc // 表示指定用什么进行编译,默认为tsc,也可以切换为webpack. 例: nest build --tsc
--watch // 表示监听文件变动,自动build.
--path // 表示指定tsc配置文件路径的.
--config // nest cli的配置文件
```

### nest start

其他选项

```js
nest start -h // 查看nest start指令下的其他选项

--watch // 表示改动文件之后自动重新build.
--debug // 表示启动调试的websoket服务,用来debug.
--exec // 表示指定用什么来跑,默认是node,也可以切换到别的runtime.
其余选项与nest build一样.
```

### nest info

```js
nest info // 可以查看项目信息,包括系统信息,node,npm和依赖版本
```

### nest-cli.json

```js
// 有些配置都可以在nest-cli.json文件中进行配置

// 比如compilerOptions里设置webpack为true就相当于 nest build --webpack,一样的效果.
// webpack设置为false就是用tsc了.

// deleteOutDir设置为true,每次build都会都清空dist目录.

// 而assets是指定nestbuild的时候,把那些非js/ts文件也复制到dist目录下.

// 可以通过include/exclude来精确匹配,并且可以单独指定是否watchAssets.

// 然后是generateOptions,这些就和我们nest generate时的--no-spec/--no-flat一样的效果.

"compilerOptions": {
    "webpack": true,
	"deleteOutDir": true,
     "watchAssets": true,
	"assets": [
        { "include": "*.env", "outDir": "dist" }
    ]
},
"generateOptions": {
    "spec": false,
	"flat": false
}
```
